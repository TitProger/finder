## Образец кода — sekvoiya, не manufacturing

Образец слоёв для новых пакетов — `/Users/fs/sekvoiya`, а не manufacturing из старого `tech-plan.md`.

Берутся устройство папок, цепочка вызова и contract-first. Не берутся предметная область кабинета (дома, курсы, партнёры, заявки риелторов), три SPA (`auth` / `admin` / `partner`), регистрация, роли `PARTNER`, Web Push, Kubernetes и визуальный UI-kit кабинета.

### Бэкенд

sekvoiya: NestJS, Fastify, MikroORM, Postgres. Слои `domain` → `application` ← `infrastructure`, сверху `interfaces`. Типы из `generated/` только в `interfaces`. Ответ — конверт `ApiResponse`. Ошибки — `AppErrors` и фильтр. Входной JSON проверяет AJV по `openapi.json`.

Вертикаль одного ресурса:

`Controller → HttpService → mapper → Application Service → Repository (порт в domain, реализация в infrastructure)`

Список и карточка сидят на общем CRUD: `CrudServiceImpl` → `CrudHttpServiceImpl` → `CrudControllerImpl` (`list`, `getById`, а запись — когда она есть в контракте). Удаление по правилам soft-delete, не «стереть строку молча». Контракт — отдельный каталог, версия git-тегом, `CONTRACT_VERSION`, `npm run contract:sync` делает checkout тега.

Finder-backend это уже частично умеет: те же четыре слоя, mapper у категорий, `generated/` не правят руками, AJV, конверт ошибок, `contract:sync`. Отличия, которые надо закрыть в своём пакете, а не заодно со всем кодом:

- Контроллер зовёт application-сервис напрямую. Прослойки `interfaces/http/services` нет.
- Общей CRUD-базы нет. Новый список или карточка пишутся на базе из sekvoiya, старые ручки на неё не переписываются, пока их пакет не наступил.
- Контракт лежит внутри того же git (`Finder-backend/api-contract`). `contract:sync` копирует текущее дерево и тег не проверяет. Целевое место — соседняя папка `Finder-api-contract`, пин по тегу, как в sekvoiya. Пока папка пустая, рабочий контракт остаётся там, где он есть. Два источника правды не заводить.
- Вход сейчас — статический `AdminTokenGuard`, не JWT и не роли sekvoiya. Экран входа — отдельный пакет 6, не часть скелета. Токен админа остаётся служебным входом в админские ручки.

Каркас Nest, Fastify, MikroORM, Postgres, Docker, CI и тесты не выбрасывать. Telegram, тарифы `free` / `unlimited` и `telegram_user_id` удаляются в том пакете, где появляется веб-замена, как уже сказано в 1.2. Адаптер «бот и сайт пишут в одни поля» не строить.

### Контракт

Форма как у `cabinet-sekvoiya-api-contract`:

- OpenAPI 3.1. Корневой `openapi.yaml` только собирает `$ref`.
- Операция — файл в `paths/<область>/`. Схемы — `components/schemas/`. Ошибки — `components/responses/errors.yaml`.
- `operationId` в camelCase. Имя tag совпадает с папкой.
- Успех — `allOf` из `ApiResponse` и `data`. Список: `page`, `limit`, `sort` и `PageInfo` в ответе.
- Описания на русском, поля в camelCase.
- Версия — git-тег. Patch — тексты, minor — новые ручки и необязательные поля, major — слом.

Существующие пути Finder (заявки, категории, ресерч) переезжают в соседнюю папку в пакете раскладки, без смены смысла ручек в том же пакете.

### Фронт

Форма как у `sekvoiya-crm-frontend`, сжатая до одного приложения:

```
Finder-frontend/
  app/site/                 один Vite SPA, один маршрут
  shared/api/               ApiClient, клиенты по тегам, contract:sync
  shared/api-types/         типы после sync
  domain/services/          вызовы API и разбор конверта
  domain/hooks/             react-query
  scripts/contract-sync.sh
```

Цепочка экрана:

`страница → hook → domain service → api-client → HTTP`

Типы после `contract:sync` лежат в generated и в git не коммитятся. Клиент читает `data` из конверта, как `requireData` в sekvoiya. Ошибки API показываются текстом кода, не сырым JSON.

Отдельного приложения `app/auth` нет: вход — маршрут того же `app/site`, пакет 6. Пакеты `app/admin` и `app/partner` не копировать. UI-kit кабинета (MUI, кабинетные таблицы) не переносить.

Вёрстка и код расходятся по образцу, не по виду. Код страницы пишется как в sekvoiya: компонент страницы, hook, domain service, api-client, типы из контракта. Вид страницы совпадает с макетом: открыть `screen.png` и повторить композицию, отступы, фон, радиусы, тени, шрифт, размеры кнопок и цвета. `code.html` — источник разметки и классов, его не вставляют в сайт целиком и не оставляют с чужими CDN-скриптами. Готово, когда экран рядом с `screen.png` читается как тот же макет, а не как «похожий». Исключения только те, что названы у конкретного экрана: чужая шапка истории, искра не как оплата, демо-числа приходят из сида, а не зашиты в JSX.

`CONTRACT_REPO` фронта указывает на `../Finder-api-contract` и тот же тег, что у бэкенда.

## Сиды для DevStand

На фронте история и карточка товара должны открываться с фото, названием и текстами из базы, а не из зашитого HTML. Для этого на локальной машине и на dev-стенде база заполняется демо-сидом. На бою этот флаг выключен.

В sekvoiya это уже устроено так, и Finder берёт ту же схему, без домов, курсов и лендинга:

- папка `backend/seed-media/` в репозитории хранит сами файлы картинок;
- рядом код сида: `src/infrastructure/database/seeders/`, внутри `data/` — тексты и относительные пути к файлам;
- общий `DatabaseSeeder` вызывает шаги по порядку;
- шаг идемпотентный: если демо-записи уже есть, повторный запуск их не дублирует;
- картинка копируется в хранилище файлов, в таблице файлов одна строка на путь, повтор того же пути не создаёт второй файл;
- `npm run seed` гоняет сид один раз без HTTP;
- переменная `PG_SEEDERS_RUN=true` гоняет тот же сид при старте API. В sekvoiya она включена только в dev-окружении (`k8s/overlays/dev`). У Finder своего Kubernetes нет: флаг включается в локальном `.env` и в env dev-стенда, в проде остаётся `false`.

Этой папки и этого оркестратора в Finder нет. Сейчас есть только `backend/seeds/categories.yaml` и сидер категорий плюс сид админа: текст справочника, без фото и без карточек товаров. Его не выбрасывать. Демо-товары садятся следующим шагом того же запуска.

Демо-набор для экранов истории и карточки, подписи помечены как демо:

- лабораторный халат, кофемолка Kitfort KT-741, умная колонка, керамический чайник;
- у каждой записи фото из `seed-media/demo/products/<slug>/`, название, категория, дата, короткое описание;
- у кофемолки ещё характеристики и четыре блока карточки: закупка, доставка, цены РФ, состав цены;
- числа в этих блоках — фикстура стенда, не живой ресерч. Блок доставки в фикстуре можно заполнить, на карточке он остаётся с пометкой демо. Боевой калькулятор по-прежнему пишет «недоступно», пока нет книги ставок владельца.

Чужие картинки из HTML (ссылки Google) в сид не класть. Файлы в `seed-media` — свои или явно демо, без чужих товарных фото без права.
